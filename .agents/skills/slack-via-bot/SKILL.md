# Slack 操作スキル（手段非依存）

チャンネル・DM・スレッドの読み取りと、承認付きの送信を行う。

## 対応できること

- 特定チャンネル・スレッドの最新メッセージを読む／自分宛メンションを拾う
- Slackbot や社内 AI アシスタントに質問して回答を読む
- チャンネル・DM へのメッセージ送信（**必ず事前提示→承認**）

## 実行手順

### 読む

1. 対象チャンネル名を確認する（`memory/projects/{name}/overview.md` のサービス座標。不明なら確認して記録）
2. 手段を解決する（`memory/service-capabilities.md` の解決順）：
   1. **コネクタ／MCP**：セッションに Slack 系ツール（例：`search_messages` / `read_channel` /
      `get_thread`）があればそれを使う
   2. **ブラウザ操作**：環境が対応していれば `https://app.slack.com/client` で対象チャンネルを開いて読む
   3. **手動アシスト**：「#{チャンネル} の該当スレッドを貼り付けてください」と依頼する
3. 関連情報を要点にまとめて報告する（人物の発言・判断が含まれていれば `person-model-update`、
   指示・依頼が含まれていれば `commitment-track` を併用する）

### 送る（要承認）

送信前に必ず内容を提示する：

```
## Slack 送信確認

**宛先**: #{チャンネル名} / @{ユーザー名}
**内容**:
{送信する全文}

▶ この内容で送信してよいですか？
```

承認後に、解決した手段（コネクタ→ブラウザ）で送信する。手段が無ければ文面を渡して
ユーザー自身の送信を依頼する。送信後は `memory/task-log/` に操作記録が残る
（Claude Code はフックが自動記録。他ホストでは秘書が1行追記する）。

## 注意事項

- 機密情報を含むチャンネルの内容は要約のみ扱い、全文を memory に残さない
- ログイン切れ・権限不足などで取得できないときは、手段を1段落として続け、ユーザーに状況を報告する
- 実在人物になりすました文面は作らない（AGENTS.md §9）
