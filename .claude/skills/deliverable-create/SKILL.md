# 成果物作成スキル（deliverable-create）

成果物の形式判断・段階的作成・保存を標準化する。**一発で全部作らない**（トークン予算の原則）。

## Step 1: 最初に1回だけ確認する（複数回聞かない）

不明な点をまとめて1メッセージで確認する：
- **宛先と用途**（誰が読む/見るか ── 上司報告・顧客提出・チーム共有で作りが変わる）
- **形式**（指定がなければ下の判断表から提案する）
- **分量の目安**（A4一枚・スライド10枚等。大きい場合はコスト確認を添える）

宛先の人物モデルが Lv2 以上なら、その人の「好む様式」を自動で反映する（例：結論先行・数字必須）。

## Step 2: 形式の判断表

**ファイル生成はホストに委ねる**。セッションのスキル一覧に該当スキル（例：`docx`・`pptx`・`xlsx`・`pdf`・
`google-workspace`）や、共有ページ／ドキュメントの作成手段（Artifact・ドキュメント系コネクタ）があればそれを使う。
このスキルは宛先・構成・段階的な作り方・保存と記録を担う。

| 依頼・用途 | ホストに手段があれば | 無ければ |
|---|---|---|
| 指定なし・報告/整理/議事 | ─ | **Markdown**（標準）で作成 |
| 見た目が必要・配布用・図表 | 共有ページ（Artifact 等） | **HTML**（単一ファイル） |
| スライド・プレゼン | `pptx` スキル／スライド作成手段 | **Marp**（`marp-cli` で PDF/PPTX に変換可と案内） |
| Word 指定 | `docx` スキル | Markdown（Word に貼り付ける前提） |
| Google スライド/Docs 指定 | `google-workspace` スキル・Drive コネクタ | **構成案＋原稿**（各スライドのタイトル・本文・発表メモ）。貼り付けで完成する形 |
| Excel/表計算 | `xlsx` スキル | CSV ＋ 整形手順 |
| PDF | `pdf` スキル | HTML を印刷して PDF 化する手順 |

**作れない形式でも止まらない**：「構成案＋流し込むだけの原稿」まで作れば作業の8割は完了する。
何が直接作成できるかは環境依存なので、その場で使える手段を確認してから約束する。

## Step 3: 段階的に作る（規模に応じて）

- **小**（A4一枚・スライド5枚以内）：直接作成してよい
- **中以上**：①アウトライン（見出し・各節1行要約・分量見込み）を提示 → ②承認 → ③本体作成。
  スライド10枚超・文書2000字超は必ずこの2段階を踏む
- 素材が memory・外部サービスに分散している場合、収集対象を先に列挙して確認する（読みすぎ防止）

## Step 4: Marp の書式（スライドの既定）

```markdown
---
marp: true
theme: default
paginate: true
---
# タイトル
発表者・日付
---
## アジェンダ
- ...
```
1スライド=1メッセージ。詰め込まない（本文は5行以内目安、詳細は発表メモへ）。
変換案内：`npx @marp-team/marp-cli slides.md -o slides.pptx`（または `-o slides.pdf`）

## Step 5: 保存と記録

- 保存先：`deliverables/{YYYY-MM-DD}-{名前}/`（プロジェクトに紐づくなら関連を明記）
- 提出・送付が必要なら下書きとして提示し承認を取る（外部送信の原則通り）
- 提出後の反応（上司のコメント等）は `person-model-update` の観察材料として人物ファイルへ
- 定型化できそうな成果物（毎週の報告等）はテンプレ化を提案（skill-improvement）

## 注意事項

- 成果物の中に認証情報・社外秘の座標（内部URL等）を不用意に含めない（宛先が社外の場合は特に確認）
- 数字・固有名詞は memory の記録と突き合わせ、根拠のない数字を作らない
- 「とりあえず全部盛り」にしない。宛先が読む時間を1分と仮定して優先順位をつける
