# 状況統合スキル

複数の情報源から現在の状況を統合し、ユーザーが即座に判断できる形で提示する。

## 実行手順

### Step 1: 対象スコープを確認する

- **プロジェクト指定あり**: そのプロジェクトの状況に集中
- **指定なし**: 全体状況を俯瞰

### Step 2: 情報を収集する

以下を並行して確認する：

**メモリから（必ず確認）**:
- `memory/situation.md` ── 現在の優先事項
- `memory/projects/{name}/status.md` ── プロジェクト状態
- `memory/projects/{name}/issues.md` ── 未解決課題
- `memory/projects/{name}/decisions.md` ── 最近の決定事項

**外部サービスから（対応可能な場合）**:
- Backlog: 期限が近いチケット・ブロッカー状態のチケット
- GitHub: 未マージPR・CIの状態
- メモリのサービス座標から直接アクセスする

### Step 3: 状況を統合して提示する

```markdown
## {プロジェクト名} の現在地 ── {日付}

### 🔴 要注意事項
（今すぐ対処が必要なもの）
- 

### 🟡 進行中
（進んでいるが監視が必要なもの）
- 

### 🟢 順調
（特に問題のないもの）
- 

### 📋 最近の決定事項
- YYYY-MM-DD: {決定内容}

### ❓ 判断待ち
（情報不足・決断が必要なもの）
- 

**情報の鮮度**: メモリ最終更新 {日付} ／ Backlog {確認日時}

**推奨アクション**:
（最も重要な次の1アクション）
```

### Step 4: 情報ギャップを指摘する

収集できなかった情報・古い情報がある場合は明記する：
```
⚠️ 以下の情報が古いか取得できていません：
- {情報名}: 最終更新 {日付}（{更新方法の提案}）
```

## 注意事項

- 収集した情報が矛盾する場合は両方を提示して判断を仰ぐ
- 推測・推論は「〜と思われます」と明記する
- サービス座標が未登録の場合は登録を促す
