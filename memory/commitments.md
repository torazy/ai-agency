# 約束台帳（commitments.md）

> Backlog に載らない粒度の「自分のタスク・受けた指示・出した指示」を一元管理する台帳。
> 会話・会議メモ・Slack から `commitment-track` スキルが抽出して追記し、
> `/morning-brief` が毎朝、期限切れ・フォロー漏れをスキャンする。
> Backlog チケットになっているものはここに**重複させない**（チケット番号への参照のみ可）。
> 完了項目は月次で `memory/archive/commitments-YYYY.md` へ退避（memory-maintenance）。

## 関連欄の記法（案件・課題・障害との紐づけ）

> タスク・指示の多くはプロジェクトや障害に紐づく。**関連欄に必ず以下の記法で記録**し、
> 案件視点の確認（synthesize-situation・morning-brief）はこの欄のフィルタで行う。
> 台帳の行をプロジェクト側にコピーしない（一元管理・重複禁止）。

| 紐づく先 | 記法 | 例 |
|---|---|---|
| プロジェクト全体 | `P:{プロジェクト名}` | `P:ecsite-renewal` |
| プロジェクトの課題 | `P:{名}/issues#{課題タイトル}` | `P:ecsite-renewal/issues#決済遅延` |
| インシデント | `P:{名}/incidents/{ログ名}` | `P:ecsite-renewal/incidents/2026-07-05-api-down` |
| Backlogチケット | `{チケットキー}` | `ECSITE-123` |
| 人物（指示者・相手） | 依頼者/相手欄に人物ファイルと同じ名前 | 田中部長 |
| 紐づきなし（純粋な単発） | `-` | `-` |

記入例：
「プロジェクトAの課題Xを整理して明日報告して」→ 受けた指示：内容=課題Xの整理と報告、
期限=明日、関連=`P:project-a/issues#課題X`
「障害対応でxxシステムの機能を調査して」→ 受けた指示：内容=xxシステム機能調査、
関連=`P:{名}/incidents/{当該ログ}`

## 記入は CLI で（表の手編集をしない）

> 行の追加・状態変更は `python tools/mem.py commitment add|set-state|list` で行う。ID（C-001…）が自動で振られ、
> 列ずれ・雛形行の残置が起きない。`list --rel P:{名}` で案件視点の抽出、`--json` でボード等から読める。
