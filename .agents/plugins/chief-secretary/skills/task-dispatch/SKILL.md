# タスク分析・分配スキル

ユーザーの要求を解体し、最適な専門家チームを編成する。

## 実行手順

### Step 1: 要求を多層解析する

```markdown
## 要求の分析

**表面的な要求**: {ユーザーが言ったこと}

**推測される真の意図**: {なぜそれを聞くのか・何を達成したいのか}

**考慮すべき暗黙の文脈**:
- {プロジェクト状況・組織状況など}

**必要な追加情報**: {判断前に確認すべきことがある場合のみ}
```

追加情報が必要な場合は1問に絞ってユーザーに確認する。

### Step 2: 関連する知識ベースをロードする

- `GEMINI.md`: 全体コンテキスト
- `memory/situation.md`: 現在の優先事項
- 関連プロジェクトの `overview.md`, `decisions.md`
- 関係する人物の `memory/people/` ファイル

### Step 3: 専門家チームを編成する

```markdown
## 専門家チーム編成

| 専門家 | 担当観点 | 優先度 |
|---|---|---|
| {専門家名} | {何を分析してもらうか} | 高/中 |
```

`memory/team/roster.md` でメンバーが在籍しているか確認する。
不在の場合は `recruit-expert` スキルを起動する。

### Step 4: 各専門家への指示書を作成する

各専門家に渡すブリーフィング：

```markdown
## {専門家名}への依頼

**背景**: {コンテキストの要約}
**具体的な問い**: {この専門家に答えてほしい具体的な問い}
**期待するアウトプット**: {何が知りたいか}
**考慮してほしい制約**: {予算・期限・組織制約など}
```

### Step 5: 並行実行または逐次実行を判断する

- **並行**: 各専門家の分析が独立している場合
- **逐次**: A の答えが B のインプットになる場合（例：コスト試算→承認判断）

逐次の場合は実行順序を明示する。

### Step 6: 結果を `cross-review` スキルに渡す

専門家の回答が揃ったら `cross-review` スキルで統合する。

## 専門家が不要なケース

以下は第一秘書が直接回答する：
- 単純な情報検索・ファイリング
- すでに `memory/` に答えがある場合
- 明らかに1つの専門分野のみで完結するシンプルな問い

その場合は対応するスキル（`intake-and-file`, `backlog-search` など）を直接起動する。
