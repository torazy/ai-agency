# /run-task ── 任せたタスクを無人で進める

ユーザー入力：`/run-task C-007`（通常は `tools/run_task.py` が無人の Claude Code で起動する）

入力（引数）: $ARGUMENTS

@chief として、約束台帳でエージェントに任せたタスクを1件進め、**結果の報告ファイルを1つ書いて終える**。
人はボードで報告を読み、「承認して完了」か、会話で手直しを頼む。

## 守ること（無人）

- `.ai-agency-template` がある（本体）か、引数が `C-数字` でなければ、何もせず1行で終える
- **質問しない・確認を待たない**。分からないことは報告の「未確認」に書いて先へ進む
- 書いてよいのは `memory/task-results/{C-ID}.md` だけ。約束の状態・記憶（人物・案件・決定・用語）・外部サービスは
  変えない。記憶に入れるべきことは報告の「記憶に入れる候補」に書く（人が承認したあと、会話で @chief が記録する）
- 外部への送信・作成・更新はしない。下書きが要るなら報告に書く
- 費用は `run_task.py` の上限で打ち切られる。大きすぎるタスクは、できた範囲と残りを報告して終える

## 手順

1. **タスクを読む**：`python tools/mem.py commitment list --json` から引数の行（内容・期限・関連・相手 @handle）を取る。
   エージェントに任せたもの（出した指示・相手が `@`）でなければ報告を書かずに終える
2. **座標を集める**：関連（`P:slug`・チケット）と内容の固有名詞を `python tools/recall.py decode "…"`／`find`／`who` で引き、
   読むべきファイルの**パスと節**を拾う（中身を丸写ししない）
3. **任せる**：Agent ツールで `subagent_type` に相手の handle（例 `generalist`）を指定して呼ぶ。
   **description は「{C-ID} {内容の要約}」で始める**（ボードの「稼働中」はこれで約束と結びつく）。
   ブリーフは CLAUDE.md §4 のとおり、事実・制約・座標・問いだけ（@chief の仮説や推奨は書かない）。最後に
   「返答は ①結論 ②根拠と出所（URL・ファイルの座標）③記憶に入れる候補（記録先の提案つき）④未確認・人の判断が要る点」と頼む
4. **報告を書く**：`memory/task-results/{C-ID}.md` を下の形で書く（同じ ID のものは上書き）。エージェントの返答を
   要約して載せ、根拠が無い主張や期限・依頼とのずれがあれば @chief として「確認」に書く
5. 標準出力には1行（「{C-ID}：結論の要点」）だけ返して終える

## 報告の形

```markdown
# {C-ID} {内容}

- 担当: @handle ／ 期限: YYYY-MM-DD ／ 関連: P:slug
- 実行: YYYY-MM-DD HH:MM（無人）

## 結論
（2〜5行。依頼に対する答え）

## 根拠と出所
- …（URL・ファイルの座標）

## 記憶に入れる候補
| 記録先 | 内容 | 出所 |
|---|---|---|

## 確認してほしいこと
- …（人の判断が要る点・未確認・依頼とのずれ。無ければ「なし」）
```

## 人が承認したあと（対話のとき）

- 起動時の案内に「報告が届いて確認待ち」が出たら、報告を読んで要点を伝え、承認を1問で聞く（承認なら `commitment set-state … done`）
- 「承認済みで記憶への反映待ち」（ボードで「承認して完了」されたもの）が出たら、報告の「記憶に入れる候補」を通常の手順
  （intake-and-file・commitment-track・person-model-update）で記録する。決定は**提案（未承認）**として入れ、「確認してほしいこと」は
  約束台帳や issues に残す。記録し終えたら `python tools/run_task.py --applied C-…` を実行し、記録先を事後報告する
- 手直しを頼まれたら、内容を `commitment set-content` で直して、ボードの「やり直させる」か `/run-task` をもう一度
