# メモリ・メンテナンススキル

記憶を「育てても軽い」状態に保つ。CLAUDE.md §6 のアーカイブ規則を実行に移すスキル。
**削除はしない。アーカイブ（退避）と圧縮（要約統合）のみ。実行前に対象一覧を提示して承認を得る。**

## 実行手順

### Step 1: 健全性スキャン

以下をチェックし、結果を表にする：

| チェック | 基準 | 対処 |
|---|---|---|
| 各 memory ファイルの行数 | 200行超 | アーカイブ提案 |
| `memory/dashboard.md` | 100行超／完了プロジェクト・疎遠な人物が表に残存 | 表の整理提案 |
| `memory/commitments.md` | `done` 行の滞留・30行超 | 月次アーカイブ（`mem.py commitment list --state done` で抽出） |
| `memory/inbox.md` | 未分類が残っている／分類済が30件超 | 未分類は秘書が仕分けて配置する（確認待ちだけ1問で聞く）。分類済は archive へ |
| `memory/projects/*/decisions.md` | `提案（未承認）` のまま30日超 | 承認か取り下げをユーザーに確認 |
| `memory/situation.md` | 「最近完了」の肥大・最終更新が2週間以上前 | アーカイブ＋更新提案 |
| `memory/projects/*/decisions.md` | 検証済み決定の滞留 | 年次アーカイブへ |
| `memory/insights.md` | 同種の学びの重複 | 原則化して統合圧縮 |
| `memory/projects/*/` | 状態が完了/凍結のプロジェクト | `_archive.md` に1行サマリーを残しフォルダごと `archive/` へ |
| 検索ミスの頻度 | `insights.md` の検索ミス記録が月3件以上 | 検索MCP（ベクトル/ハイブリッド）の導入を capability-expansion で提案 |

**検索ミスの記録**：日常運用で「記録したはずの情報を見つけられなかった」事象が起きたら、
その都度 `insights.md` に「🔍検索ミス: {探した語} → 実際の場所 {パス}」と1行記録する（全スキル共通）。
この件数が検索基盤を強化するタイミングの判断材料になる。markdown が正典なので、
検索インデックスは後からいつでも再構築可能（データ移行不要）。

### Step 2: アーカイブの実行（承認後）

- 退避先：`{同フォルダ}/archive/{ファイル名}-YYYY.md`（なければ作成）
- 退避時は元ファイルの先頭に「過去分: archive/... 参照」の1行を残す
- **要点は残す**：decisions のアーカイブでは学びを `insights.md` に1行ずつ転記してから退避

### Step 3: insights の統合圧縮（四半期に1回程度）

- 同じ教訓を語る複数の事例を「原則」1項目に統合する（例：3件の見積り超過事例 → 「@accountant 系の
  見積りは1.3倍で見る」）。統合元の事例は archive へ
- 人物ファイルの「判断事例ログ」は**圧縮しない**（/simulate の予測精度の源泉。行数超過時も
  古い事例を人物別 archive に移すだけにする）

### Step 4: レポート

```
## メモリ・メンテナンス結果（YYYY-MM-DD）
- 📦 アーカイブ: {ファイル} {n}行 → {退避先}
- 🗜 統合: insights {n}件 → {m}原則
- ⚠️ 要判断: {ユーザーの判断が要るもの（例: プロジェクトXは完了扱いでよいか）}
- 現在の常時ロード量: dashboard.md {n}行（上限100）
```

## 注意事項

- ガードレール（guardrails.json）・delegation.md・CLAUDE.md はこのスキルの対象外（勝手に触らない）
- アーカイブはユーザー承認後に実行（Level 2 以上で自律化可）
- 月次実行の登録：デスクトップの定期タスク（「毎月1日9:00に memory-maintenance を回して」）。`memory/briefs/` の30日より古いブリーフも削除してよい（gitignore 済みの生成物）
