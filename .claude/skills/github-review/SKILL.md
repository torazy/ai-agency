# GitHub レビュースキル

GitHub MCPツールを使ってPR・Issue・CIの状態を確認し、レビューを支援する。

## 使用するMCPツール

- `github_list_pull_requests`: PR一覧取得
- `github_get_pull_request`: PR詳細取得
- `github_get_pull_request_diff`: PR差分取得
- `github_list_issues`: Issue一覧取得
- `github_get_issue`: Issue詳細取得

## 実行手順

### リポジトリ情報の取得

リポジトリ名は `memory/projects/{name}/overview.md` のサービス座標から取得する。
フォーマット: `{owner}/{repo}`

### PR一覧・状態確認

```markdown
## {リポジトリ名} PR 状態 ── {日付}

### 🔴 要対応
（Draft以外・レビュー待ち・CIエラー）
| PR# | タイトル | 作者 | 最終更新 | 状態 |
|---|---|---|---|---|

### 🟡 レビュー中
| PR# | タイトル | 作者 | 最終更新 |
|---|---|---|---|

### 🟢 承認済み・マージ待ち
| PR# | タイトル | 作者 |
|---|---|---|
```

### コードレビュー支援

PRの差分を取得して以下の観点でコメントを提示する：

1. **バグ・論理エラーの可能性**: 明確な問題を指摘
2. **セキュリティ（OWASPトップ10）**: インジェクション・認証・機密情報露出など
3. **コードの明瞭さ**: 命名・コメントの適切さ
4. **テスト**: テストカバレッジの確認

```markdown
## PRレビュー：#{PR番号} {タイトル}

**変更ファイル数**: {数}
**追加行数**: +{数} / **削除行数**: -{数}

### 🔴 必須対応
（バグ・セキュリティ問題）
- `{ファイル名}:{行番号}` ── {問題と理由}

### 🟡 推奨対応
（改善提案）
- `{ファイル名}` ── {提案内容}

### 🟢 良い点
- {ポジティブなフィードバック}

### 総評
（マージ可否と理由）
```

## 注意事項

- レビューコメントをGitHubに投稿する前に必ず内容を提示して確認を取る（`github-manage` スキル参照）
- プライベートリポジトリへのアクセスにはGitHub PATが必要
- 大きなPR（変更ファイル30以上）は分割してレビューを提案する
