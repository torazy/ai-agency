# テストインスタンス（本体メンテ用）

本体フォルダでは製品が無効化されている（`tools/dev/README.md`）。記憶に書く動作の確認は、
本体の隣に作った使い捨てインスタンスで行う。**テストインスタンスは push しない**。

## 作る

本体のルートで：
```bash
git clone . ../ai-agency-test
```
- 本体のローカル履歴がそのまま入る（未コミットの変更は入らない。試したい変更は先にコミットする）
- `../ai-agency-test` を Claude Code で**別フォルダとして開く**と製品が起動する
  （ここには `CLAUDE.local.md` も `settings.local.json` も無いので、インスタンスと同じ条件になる）
- `.env` が必要な確認（Backlog MCP 等）は、本体の `.env` を手でコピーする（コミットされない）

## 試す

テストインスタンスのセッションで：
1. 新規セッションの冒頭に「[記憶の状態] memory/ は未初期化…」が注入されるか（SessionStart フック）
2. `/setup` を通して memory/ が埋まるか、質問の粒度・順番が自然か
3. 外部書き込み（例：memory/ への Write）で `memory/task-log/YYYY-MM.md` に `**操作**:` 行が付くか
4. 気づいた改善点は**本体側のセッション**に戻って正典（`CLAUDE.md`・`.claude/`）を直す（テストインスタンスで
   直すと、本体に還流し忘れて消える）

## 更新する（本体の新しいコミットを取り込む）

テストインスタンスのルートで：
```bash
git pull
```
（clone 元が本体なので `origin` = 本体ローカル。memory/ の変更と衝突したら、テストデータなので
テストインスタンス側を捨ててよい）

## 片付ける

テストインスタンスのフォルダは**ユーザーが手で削除する**（エクスプローラー等）。本体の `permissions.deny`
が再帰削除コマンドを封じているため、秘書・エージェントからは削除しない。削除前に、残したい観察
（使いにくかった点）があれば `tools/dev/memory/roadmap.md` に転記する。

## 注意

- テストインスタンスの memory/ に**実在の人物・案件の実データを入れない**（使い捨て前提）。ダミーデータで試す
- 実運用のインスタンスでの確認は OPERATIONS.md §3（upstream merge）の手順で、ユーザー自身が行う
