# AI秘書チーム 名簿（roster.md）

最終更新: 2026-05-31

> 専門家の定義は `.claude/agents/{handle}.md`（@chief の人格は `CLAUDE.md` §1）。`/consult` が必要時に
> Agent ツールで**独立コンテキストのサブエージェント**として召集する形でチームになる。
>
> **この名簿はAI支援チーム専用。** 実在の上司・メンバー・顧客の思考モデル（`/simulate` 用）は
> ここには載せず、`memory/people/{識別子}.md` に観察を蓄積する（成熟度 Lv0〜Lv3 は各ファイルに記載）。

## チーム構成

| エージェント名 | 役割 | 専門領域 | トリガー条件（例） | ステータス |
|---|---|---|---|---|

| **accountant-agent** | 経理専門家 | コスト分析・ROI・予算・財務リスク | 費用・投資・コスト比較・予算計画 | ✅ 稼働中 |
| **hr-agent** | 人事専門家 | 採用・評価・組織設計・労務コンプライアンス | 採用・組織変更・評価制度・人員計画 | ✅ 稼働中 |
| **dx-agent** | DX専門家 | 業務プロセス改善・自動化・システム化・変革管理 | 業務効率化・ツール導入・デジタル化 | ✅ 稼働中 |
| **pm-agent** | PM専門家（PMP） | プロジェクト計画・スケジュール・リスク管理・ステークホルダー | 進捗管理・計画策定・リスク評価 | ✅ 稼働中 |
| **qa-agent** | 品質専門家（QA） | テスト設計・品質基準・バグ管理・セキュリティテスト | 品質レビュー・テスト計画・リリース判定 | ✅ 稼働中 |
| **it-architect-agent** | ITアーキテクト | システム設計・技術選定・クラウド・セキュリティ・スケーラビリティ | 技術選定・システム設計・インフラ決定 | ✅ 稼働中 |

## 専門領域クロスマトリクス

どの専門家がどのテーマをカバーするか。

| テーマ | 主担当 | 連携先 |
|---|---|---|
| コスト・予算・ROI | 経理（accountant） | PM（コスト制約）、DX（効率化効果） |
| 採用・組織・評価 | 人事（hr） | 経理（人件費）、PM（体制計画） |
| 業務効率化・自動化 | DX（dx） | ITアーキテクト（技術面）、経理（コスト） |
| プロジェクト計画・進捗 | PM（pm） | QA（品質計画）、経理（予算） |
| 品質・テスト・セキュリティ | QA（qa） | ITアーキテクト（セキュリティ設計）、PM（スケジュール） |
| システム設計・技術選定 | ITアーキテクト（it-architect） | QA（テスト観点）、DX（業務連携）、経理（コスト） |
| 契約・規約・法的リスク | 法務（legal） | HR（労務）、経理（財務コンプライアンス）、ITアーキ（データ・セキュリティ要件） |
| 情報収集・検索・サービス連携 | 汎用秘書（ai-secretary） | 全専門家（情報提供） |
| 複合的な意思決定 | 第一秘書（chief-secretary） | 必要な専門家全員 |
| テーマ別の議論（/discuss） | 第一秘書（司会） | 指名された専門家＋人物モデル（Lv1 以上・予測として参加） |

## 新規専門家の召集方法

チームに不足している専門知識があると判断した場合、`recruit-expert` スキルを使って `.claude/agents/` に新しいペルソナ（`## The 役割 (@handle)`）を追加提案できます。追加後は `/consult` がそのペルソナを動的サブエージェントとして召集します。

### 現在の空きポジション（候補）

| 想定役割 | 想定専門領域 | 必要になる状況 | ステータス |
|---|---|---|---|
| **法務専門家** | 契約審査・コンプライアンス・利用規約 | 契約・法令対応が増えた場合 | ✅ 稼働中（legal-agent）|
| **マーケティング専門家** | 戦略・競合分析・ブランディング | 事業戦略・広報判断が必要な場合 | 🔲 未召集 |
| **データアナリスト** | KPI分析・BI・データドリブン意思決定 | 定量分析の需要が高まった場合 | 🔲 未召集 |
