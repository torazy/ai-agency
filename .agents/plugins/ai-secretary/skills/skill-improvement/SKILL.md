# スキル改善スキル

既存スキルの問題を分析し、改善案を提示・実装するプロセス。

## トリガー条件

- 同じ種類のタスクで繰り返し失敗・不満足な結果が出た
- ユーザーが「このやり方は違う」「もっと〇〇してほしい」とフィードバックした
- ユーザーが「このスキルを改善して」と明示した
- スキルの手順が実際の業務フローと合っていないと気づいた

## 実行手順

### Step 1: 問題を特定する

```
## スキル改善分析

**対象スキル**: {スキル名}
**発見された問題**:
- （具体的に何が問題か）

**影響**:
- （どんな不具合・非効率が起きているか）

**根本原因**:
- （なぜこの問題が起きているか）
```

### Step 2: 改善案を作成する

現在のスキルファイルを読み込み、変更箇所を特定する。

改善の方向性：
- **手順の追加**: 見落としていたステップを追加
- **条件の明確化**: 曖昧なトリガー条件を具体化
- **フォーマットの調整**: アウトプット形式をユーザーの好みに合わせる
- **エラー処理の追加**: 失敗ケースへの対処法を追加

### Step 3: 変更内容をユーザーに提示する

```markdown
## スキル改善案：{スキル名}

**変更箇所**:
（変更前と変更後を対比して示す）

変更前:
> （現在の記述）

変更後:
> （改善後の記述）

**この変更によって改善されること**:
- 

▶ この改善を適用してよいですか？
```

### Step 4: 承認後に実装する

スキルファイルを更新する。
`memory/insights.md` に改善内容を記録する：

```markdown
## {日付}: {スキル名} の改善

**問題**: 
**改善内容**: 
**効果**: 
```

## 新規スキル作成の判断基準

以下の条件をすべて満たす場合、改善ではなく新規スキルとして作成を検討する：

- 既存スキルとは明確に異なる用途である
- 繰り返し発生する具体的なユースケースがある
- 独立したトリガー条件がある

新規スキル作成の場合は `capability-expansion` スキルの手順に従う。

## 注意事項

- スキルの改善は必ずユーザーの承認を得てから実施する
- 改善後も元の設計意図を保つ（大幅な方向転換はユーザーに確認）
- `plugin.json` のスキルリストに新規スキルを追加することを忘れない
