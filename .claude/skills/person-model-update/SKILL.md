# 人物モデル更新スキル

実在人物の「考え方・行動」の観察をペルソナモデルとして蓄積するプロセス。
`intake-and-file` が情報の置き場所を決めるのに対し、このスキルは**人物の思考・反応パターンの抽出**に特化する。

## トリガー条件

以下のいずれかで起動する（`/intake` の処理中に該当を検知した場合も含む）：

- 会議メモ・議事録に特定人物の発言・判断が含まれる
- Slack会話・メールに人物の反応（承認・差し戻し・質問・懸念）が含まれる
- ユーザーが「〇〇さんにこう言われた」「部長がこう判断した」と話した
- `/simulate` の予測に対して実際の反応が判明した（→ 検証テーブルに記録）
- 人と関わったタスクの完了後（CLAUDE.md §7 の自己改善ルーティン）

## 実行手順

### Step 1: 人物を特定する

1. `memory/people/` の既存ファイルを確認する（ファイル名は `{姓}-{名}-{所属略称}-{役職略称}.md`）
2. ファイルがなければ `_template.md` から新規作成を提案する（一意識別子の確認を忘れない）
3. 同姓同名の可能性があれば所属・識別子で確認する

### Step 2: 観察を抽出する

持ち込まれたテキスト・会話から以下を分離して抽出する：

- **判断事例**（最重要）: 「状況 → 本人の判断・言動 → 理由」のセット
  - 理由は本人が明言したか、こちらの推測かを必ず区別する（推測なら「（推測）」）
- **反応パターン**: 質問の仕方、承認/差し戻しの基準、感情的な反応点
- **表現・様式**: 口癖、好む報告形式、コミュニケーション経路の好み
- **予測の答え合わせ**: 「反応予測と検証」テーブルに未検証の予測があり、今回の情報で
  実際の反応が分かる場合は、実際の反応・判定・学びを追記する

### Step 3: 人物ファイルに書き込む

書く前に `python tools/recall.py who {名前}` で人物を特定する（0件・2件以上は確認ケース）。既存の判断事例は `python tools/recall.py show memory/people/{識別子}.md --section 判断事例` で見る。

| 抽出したもの | 書き込み先セクション | 操作 |
|---|---|---|
| 判断事例 | 判断事例ログ | `python tools/mem.py person observe {識別子} --situation … --judgment … --reason …` |
| 反応・思考の傾向 | 思考・行動特性／判断の癖（仮説） | 本文を追記・更新（観察回数を添える） |
| 口癖・様式 | ペルソナモデルの各項目 | 本文を追記・更新 |
| 予測の答え合わせ | 反応予測と検証 | 該当行に実際の反応・判定・学びを追記（この更新は手編集でよい） |
| 単発の気づき | 過去のやりとり・気づき | `python tools/mem.py person note {識別子} --situation … --insight …` |
| アイコン（ボード表示用） | 基本情報 | `python tools/mem.py person set-icon {識別子} {絵文字|アイコン名}`（`person new --icon` でも可） |

**帰属が曖昧なら書く前に確認する**（誰の発言・判断か特定できない観察は人物モデルを汚す）。

書き込み前に既存内容を読み、**矛盾があれば上書きせず併記して観察日を残す**
（人の行動は変わる。古い仮説を消すのは3回以上反証されたときのみ）。

### Step 4: モデル成熟度を再評価する

| 条件 | 成熟度 |
|---|---|
| 基本情報のみ | Lv0 |
| 特性の仮説が1つ以上ある | Lv1 |
| 判断事例ログが5件以上 | Lv2 |
| 反応予測の的中（判定=予測通り）が2件以上 | Lv3 |

昇格したら成熟度の行を更新し、ユーザーに報告する
（例：「田中部長のモデルが Lv2 になりました。/simulate で報告前の反応予測に使えます」）。

### Step 5: 簡潔に報告する

```
👤 人物モデルを更新しました：
- {ファイル名}: 判断事例 +{n}件、特性更新 {あれば}（成熟度 Lv{x}）
```

## 注意事項

- **本人の発言は原文の趣旨を保つ**。要約で意図を歪めない
- 推測と観察事実を混ぜない（推測には必ず「（推測）」）
- ネガティブな観察（地雷・避けるべき点）も記録するが、**評価・断定ではなく観察として**書く
  （例：「×：短気な人」「○：結論が遅い報告を2回遮った（2026-06-15, 06-28）」）
- 人物ファイルはこのリポジトリ内に留める。外部サービスへの転記・共有はしない
