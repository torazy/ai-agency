# /scout ── 提案役（仕事を見つける）

ユーザー入力：`/scout`（任意で `--unattended`・`P:slug` で案件を絞る）

入力（引数）: $ARGUMENTS

@chief が**提案役**として、頼まれていないが必要な仕事を見つける。**見つけるだけで、実行も割り振りもしない**
（採用・保留・却下・統合は割り振り役 /dispatch の責任）。1件ずつ `python tools/work.py propose` で積む。

## 1. 機械的に見つかるもの（先に・トークンを使わない）

```bash
python tools/work.py changes --propose   # 参照している情報の変化（待ちの解消・前工程の完了・前提の変化・完了済みの根拠の変化）
python tools/work.py scan --propose      # フォロー日が来た依頼・期限3日以内で未着手
```

同じ変化・同じ期限からは二度提案されない（起因の指紋）。

## 2. 観察して見つけるもの（読むのは座標と該当節だけ）

| 見る | 見つける仕事の例 |
|---|---|
| 予定（カレンダーが使えれば今日〜14日）・`situation.md` | 会議や期限から逆算した準備（資料・論点整理・事前の根回し）。会議が前倒しされた → 準備の期限を詰める |
| 約束台帳（`commitment list --json`）・作業記録の実行履歴 | 返答待ちが長い依頼のフォロー、進捗が止まったタスク、差し戻しが続くタスク、前工程が終わったのに後工程が無い |
| 案件の `overview.md`（目的・期限）・`status.md`・`issues.md` | 目的に対して誰も持っていない作業（目的にあるのに約束が無い）、期限から逆算して足りない工程 |
| 新しく入った情報（`inbox`・直近の取り込み・`/update`） | 再調査・再検討（料金改定・仕様変更・上司の新条件）、既存の成果物や計画の更新 |
| `insights.md`・操作ログ・`memory/briefs/review.md` | 繰り返し起きる問題への改善（同じ指摘が3回・同じ手戻り） |
| 決定（`decisions.md` の検証日・提案のまま7日） | 予測の検証、承認待ちの催促 |

## 3. 提案の書き方（5つ必須）

```bash
python tools/work.py propose \
  --what "11/12 定例の論点メモを作る（比較表の差分と未決事項）" \
  --why "定例が 11/14 → 11/12 に前倒しされた（2日短くなった）" \
  --evidence "memory/projects/kintai-saas/status.md#予定・C-002" \
  --effect "定例で決め切れる・差し戻しを防ぐ" \
  --who "@pm"
```

- **何をするか**：担当が着手できる粒度で1文（目的と成果物が分かる）
- **なぜ今必要か**：期限・会議・変化など「今」である理由
- **根拠**：記憶の座標（パス#節・C-ID・D-ID）か出所。根拠の無い思いつきは提案しない
- **期待する効果**：何が防げる・何が進むか
- **担当候補**：@handle（専門）か @chief。人に頼む仕事なら相手の名前
- 変化に由来するものは `--key "C-007|場所|新しい版"`（work.py changes の key）を付ける。観察なら省略

## 4. 出さないもの

- 既にある約束・作業記録と同じ仕事（統合の候補として「既存の C-xxx に足す」と書くのはよい）
- 根拠が記憶にも出所にも無いもの、効果が説明できないもの
- 1回の見直しで出すのは多くても 7 件まで（優先度の高い順）。多すぎる提案は割り振りを詰まらせる

## 5. 終わり

対話なら「提案 n 件（S-…）。採否は /dispatch か、ボードの提案から」と1行で伝える。無人なら何も聞かずに終える。
