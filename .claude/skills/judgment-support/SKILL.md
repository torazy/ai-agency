# 判断支援スキル

ユーザーの意思決定を支援するため、状況・選択肢・推奨を構造化して提示する。

## 実行手順

### Step 1: 判断に必要な文脈を収集する

**メモリから**:
- `memory/projects/{name}/decisions.md` ── 過去の類似決定
- `memory/projects/{name}/context/` ── 関連する背景知識
- `memory/projects/{name}/issues.md` ── 現在の制約・問題
- `memory/insights.md` ── 過去の学習内容

**外部から（対応可能な場合）**:
- Backlog: 関連チケットの状態
- GitHub: 技術的な制約・PR状態

### Step 2: 不足情報を特定する

判断に必要なのに分からない情報を列挙する。
ただし、情報不足でも判断支援を完全に止めない──
「〇〇が分かれば精度が上がる」という形で補足する。

### Step 3: 判断を構造化して提示する

```markdown
## 判断支援：{課題のタイトル}

### 現在の状況（事実）
（客観的事実のみ。推測はここに含めない）
- 

### 制約・前提条件
- 

### 選択肢

**A) {選択肢A}**
- メリット: 
- リスク: 
- コスト: 

**B) {選択肢B}**
- メリット: 
- リスク: 
- コスト: 

**C) {選択肢C}**（あれば）
- メリット: 
- リスク: 
- コスト: 

### 推奨：**A**

理由：（具体的な根拠を2〜3点）

過去の参考事例：（decisions.md から類似決定があれば）

### 不確かな点
（明らかになれば判断が変わりうる情報）
- 

### 判断を変えうるトリガー
- {条件} の場合は B を選ぶべき
```

### Step 4: 決定後のファイリングを提案する

```
決定後、`decisions.md` に記録しますか？
理由を残しておくと将来の判断に活用できます。
```

## 注意事項

- 推奨は必ず1つに絞る（「どちらも一長一短」は回答として不十分）
- 推奨の根拠は必ず具体的に示す
- ユーザーが別の選択肢を選んだ場合でも、決定内容をファイリングする
- 感情的・政治的な判断はユーザーに委ねる（事実と選択肢のみ提示）
