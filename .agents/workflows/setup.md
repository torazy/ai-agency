# /setup ── オンボーディング（記憶の初期化・冪等）

ユーザー入力：`/setup`（または秘書が「dashboard 未設定」を検知して提案）

あなたは @chief として振る舞う。この仕組みの大半（/simulate・/morning-brief・/propose-delegation・
/review-decisions・/consult の文脈読込）は**記憶が育ってから効く**。最初の15分で「最低限の記憶」を作り、
以後は日常会話と `/intake` で育てる。

**進め方の規則**
- 一度に全部聞かない。**1ステップにつき質問は1〜3問**。答えがない項目は「あとで」で飛ばせると毎回伝える
- 推測で埋めない。未回答は「（未設定）」のまま残す
- 書き込み前に既存ファイルを読む。設定済みの項目は表示して「変更はありますか」とだけ聞く（再実行可）
- 記録先・書式は AGENTS.md §6 と `intake-and-file` スキルに従う。原文コピーではなく要点

## Step 0: 現状診断（聞かずに自分で確認）

以下を確認し、1つの表で「どこまで育っているか」を示す：

| 項目 | 確認方法 | 判定 |
|---|---|---|
| ユーザープロファイル | `memory/dashboard.md` の「（未設定）」の有無 | 未設定 / 設定済 |
| 進行中プロジェクト | `memory/projects/*/overview.md` の件数 | 0件 / n件 |
| 人物 | `memory/people/*.md`（`_template.md` 除く）の件数 | 0件 / n件 |
| 約束台帳 | `memory/commitments.md` の「（未登録）」以外の行数 | |
| 操作実績 | `memory/task-log/*.md` の `**操作**:` 行数 | 0 → /propose-delegation は未稼働 |
| 優先事項 | `memory/situation.md` の最終更新日 | |

すべて設定済みなら「環境の棚卸し（Step 1）だけ更新しますか？」と聞いて Step 1 → Step 7 に短縮する。

## Step 1: 利用可能ツールの棚卸し（ユーザーに聞かず自分で確認）

1. **このセッションで実際に呼べるもの**を列挙する：MCP/コネクタ（ツール名の接頭辞 `mcp__{server}__` で
   サーバーを識別）、ブラウザ操作の有無、ホスト固有の定期実行機能の有無
2. 接続に失敗しているサーバー（例：`CONNECTION_CLOSED`）は**報告し**、`.env` と MCP 設定の確認を案内する
   （勝手に設定変更しない）
3. `memory/service-capabilities.md` の「**観測記録**」表に、ホスト名・日付・サービス別の使えた手段を
   1行で追記/更新する（同じホストの古い行は上書き）

出力例：
```
## このセッションで使える手段（{ホスト名}・{日付}）
| サービス | 手段 | 備考 |
|---|---|---|
| GitHub | MCP（github） | |
| Backlog | ✕ 接続失敗 | .env の BACKLOG_API_KEY を確認 |
| Google Calendar | コネクタ | 読み取り・作成可 |
| Slack | 未接続 → 手動アシスト | |
```

## Step 2: あなたのこと（2〜3問）

聞くこと：①名前と呼び方 ②役職・担当領域・主な責任範囲 ③判断基準の優先順位
（例：「品質 > スピード > コスト」「顧客影響を最優先」）。余裕があれば返答の好み（長さ・言語・敬体）。

→ `memory/dashboard.md`「ユーザープロファイル」「判断基準・優先順位」を更新、
　`memory/user-profile.md` の基本情報・コミュニケーションの好みを更新。

## Step 3: 進行中の案件（1件ずつ・3件まで）

案件ごとに聞くこと：名前・目的・状態・期限・優先度、**サービス座標**（Backlog プロジェクトキー /
GitHub リポジトリ / Drive フォルダ URL / Slack チャンネル）、主な関係者。
座標が分からなければ「（未登録）」で作り、後で `/intake` に貼れば登録できると伝える。

→ `memory/projects/{slug}/overview.md` と `status.md` を作成（`intake-and-file` の書式）、
　`memory/dashboard.md` のプロジェクト表に1行追加。slug は英小文字とハイフン。
4件目以降は「残りは後で /intake で登録しましょう」と区切る。

## Step 4: よく関わる人（Lv0 で可・5名まで）

人物ごとに聞くこと：氏名・所属・役職・関係の種別・**一意識別子**（メール / Backlog / GitHub / Slack の
いずれか1つ以上）・分かっていれば判断スタイルを1行。

→ `memory/people/_template.md` から `memory/people/{姓}-{名}-{所属略称}-{役職略称}.md` を作成
　（成熟度 Lv0。特性が1つでも聞けたら Lv1）、`memory/dashboard.md` の人物表に追加。
「会議メモや Slack を /intake で流すと判断事例が貯まり、5件で /simulate が実用になります」と伝える。

## Step 5: いまの優先事項と約束（2問）

聞くこと：①今週の最重要事項（3つまで）と判断待ちの事項 ②いま受けている指示・出している指示で
期限があるもの。

→ `memory/situation.md` を更新（最終更新日を必ず記入）、
　`memory/commitments.md` に `commitment-track` の記法で追記（関連欄に `P:{slug}` を付ける）。

## Step 6: 定期実行の登録を案内する

推奨セットを提示し、**ユーザーが承認したものだけ**ホストの仕組みで登録する
（Antigravity＝`/schedule`、Claude Code＝scheduled task / `/schedule` スキル、Hermes＝内蔵 cron、
Copilot＝不可なので他ツールを案内）：

| 周期 | コマンド | 目的 |
|---|---|---|
| 毎朝 | `/morning-brief` | 先回りの状況整理（Duet 的な常時稼働の入口） |
| 週次（金） | `/review-decisions` | 予測 vs 実際の答え合わせ |
| 週次（月） | `/propose-delegation` | 承認実績から自動承認への昇格提案 |
| 月次 | `memory-maintenance` | 記憶を育てても軽く保つ |

## Step 7: 完了報告

```
## セットアップ完了
- 📁 作成/更新したファイル: {一覧}
- 🧰 使える手段: {Step 1 の要約1行}／未接続: {あれば}
- 🌱 育成度: プロフィール ✅ ／ 案件 {n}件 ／ 人物 {n}名（Lv0〜1）／ 約束 {n}件 ／ 操作実績 0（これから貯まる）
- ⚠️ 未設定のまま: {あれば}

**次のアクション**: {具体的1つ。例「明日の朝 /morning-brief を試す」「会議メモを1本 /intake に貼る」}
```

`memory/dashboard.md` が 100 行以内であることを確認して終える。
