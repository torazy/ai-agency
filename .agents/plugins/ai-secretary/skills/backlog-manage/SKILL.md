# Backlog 管理スキル

BacklogのMCPツールを使ってチケットを作成・更新・コメント追加する。
**すべての操作は実行前にユーザーへ内容を提示して確認を取ること。**

## 使用するMCPツール

- `backlog_create_issue`: チケット作成
- `backlog_update_issue`: チケット更新
- `backlog_add_comment`: コメント追加

## 共通ルール：実行前確認

操作実行前に必ず以下の形式で提示する：

```
## Backlog 操作確認

**操作**: {作成 / 更新 / コメント追加}
**対象**: {プロジェクト名} / #{チケット番号}
**内容**:
（実際に送信される内容を全文表示）

▶ この内容で実行してよいですか？
```

承認を得てから `backlog_*` ツールを呼び出す。

## チケット作成の手順

### Step 1: 必要情報を収集する

- **プロジェクト**: `memory/projects/{name}/overview.md` の Backlog プロジェクト ID を使用
- **タイトル**: 明確な動詞で始める（例：「〇〇機能を実装する」「〇〇のバグを修正する」）
- **種別**: タスク / バグ / 要望 / その他
- **担当者**: ユーザーが指定しない場合は未割り当て
- **期限**: ユーザーが指定した場合のみ設定
- **優先度**: 中（デフォルト）
- **説明**: 内容・背景・完了条件を含める

### Step 2: 内容を確認して実行する

確認フォームを提示 → 承認後 → `backlog_create_issue` 実行

### Step 3: 完了報告

```
✅ Backlog チケットを作成しました。

**チケット**: #{番号} {タイトル}
**URL**: {チケットURL}

memory/projects/{name}/issues.md に追記しますか？
```

## チケット更新の手順

### Step 1: 更新対象を特定する

チケット番号が不明な場合は `backlog-search` スキルで検索する。

### Step 2: 現在の内容を確認する

`backlog_get_issue` で現在の状態を取得し、変更箇所を明確にする。

### Step 3: 変更内容を確認して実行する

変更前 → 変更後を対比して確認フォームに表示する。

## コメント追加の手順

コメント内容を全文表示して確認を取る。
Markdown記法が使用可能なことを念頭に、読みやすい形式で記述する。

## 注意事項

- プロジェクト ID は必ずサービス座標から取得する（ハードコードしない）
- 関係者への通知はBacklogの設定次第。送信確認はこのスキルの対象外
- チケット削除は禁止（`delegation.md` 参照）
