# 独立レビュー（independent-review）

作った者の自己点検では、依頼とのずれ・根拠のない断定・宛先に合わない書き方を見落とす。**別の文脈のレビュアー**に
「依頼・成果物・基準」だけを渡して見てもらう。CLAUDE.md §4 の独立性（1つの文脈で全役を演じない）の延長。

## 1. 仕事を受けたら、最初に進め方を1行で宣言する

作業に入る前（約束台帳に載せた直後）に、担当とレビューの有無を**理由つきで**示す。聞くのではなく宣言する
（ユーザーは変えたいときだけ言う）。Level 1 で実行前の確認を取るなら、その確認に含める。

```
▶ 進め方：@pm が作成 → @qa がレビュー（部長に出す提案書のため）／期限 11/10。変えるなら一言ください
▶ 進め方：@generalist が調べる（レビューなし：社内の下調べのため）／期限 11/7
```

エージェントに任せたタスク（相手が `@handle`）は、宣言した内容を残す（ボードと無人実行が従う）：
`python tools/run_task.py --plan C-007 --review qa --reason "部長に出す提案書"`（なしは `--review none`）。
ユーザーが「レビューなしで」「@legal にも見せて」と言ったら、同じ命令で直す。

### レビューを付けるか（難易度と影響で決める）

| 付ける | 付けない |
|---|---|
| 人の手に渡る（上司・顧客・社外・他部署） | 社内の下調べ・情報収集・メモ |
| 決定・予算・契約・人事の判断材料になる | 下書き（ユーザーがすぐ自分で手を入れる） |
| 複数の領域にまたがる（費用×法務×技術など） | 単純作業（転記・一覧化・日程の候補出し） |
| 根拠が記憶や出所でなく経験則に寄りやすい | 結論が記憶の事実をまとめただけ |
| 誤りが高くつく（数値・期日・約束・法令） | すでに専門家同士で議論した（/discuss の結論） |

迷ったら付ける。ただし同じ相手・同じ種類の成果物で「指摘なし」が3回続いたら、次からは外す提案をしてよい。

### レビュアーを選ぶ

- 専門の観点が要る → その専門家（契約・規約は @legal、費用・ROI は @accountant、設計・セキュリティは @it-architect、
  計画・スケジュールは @pm、業務改善は @dx、人事は @hr）
- 専門の観点が要らない → @qa（依頼への適合・根拠・一貫性・宛先）
- **作成者は自分の成果物をレビューしない**。作成者が @qa なら @generalist に頼む
- 1件に付けるレビュアーは原則1人（2人以上は、領域が本当に2つあるときだけ）

## 2. レビューを頼む（Agent ツール・別の文脈）

- `subagent_type` にレビュアーの handle、description は「{C-ID} レビュー：{要約}」（ボードの稼働に出る）
- ブリーフに渡すのは **①元の依頼（約束台帳の行・宛先・期限）②成果物の全文（または座標）③下の基準** だけ。
  作成者の考え・@chief の評価・「良さそうだが」等の感想は**渡さない**（引っ張られる）
- 返答の形を指定する：

```
判定: OK / 要修正
重大な指摘（直さないと渡せない）:
- [箇所] 何が問題か → どう直すか
軽微な指摘（直すとよい）:
- …
良い点（1〜2行）:
```

### 基準（レビュアーに渡す）

1. 依頼に答えているか（問い・範囲・期限・宛先とずれていないか）
2. 主張に根拠と出所があるか（記憶の座標・URL）。推測・経験則はそう書かれているか
3. 数値・日付・固有名詞が出所と合っているか、内部で矛盾していないか
4. 宛先に合っているか（宛先の人物モデルがあれば、その人の「好む様式」）
5. 抜けている観点・リスク（レビュアーの専門から）

## 3. 直す（1回まで）

- **重大な指摘があれば**、作成者に1回だけ直させる（同じエージェントに続きを送るか、元のブリーフ＋成果物＋指摘で呼び直す）。
  軽微な指摘は @chief が直すか、そのまま残す
- 直した結果を**もう一度レビューに回さない**（往復で費用が膨らむ）。直しきれなかった指摘は「残った指摘」に書く
- レビュアーと作成者の意見が割れたら、@chief は裁かずに**両論を並べて**ユーザーに見せる

## 4. 記録する

成果物（または /run-task の報告）の末尾に「レビュー」の節を付ける：

```markdown
## レビュー
- レビュアー: @qa ／ 判定: 要修正 → 修正済み（1回）
- 指摘と対応:
  - [重大] 期限の根拠が無い → overview.md の行を出所に追記
  - [軽微] 表の単位が混在 → そのまま（残った指摘）
- 残った指摘: …（無ければ「なし」）
```

レビューを付けなかったときは「レビュー: なし（理由）」と1行だけ書く。繰り返し出る指摘（同じ種類が3回）は
`insights.md` に学びとして書き、手順やルールに上げる（skill-improvement）。
