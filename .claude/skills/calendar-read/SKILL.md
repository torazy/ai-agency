# カレンダー読み取りスキル（手段非依存）

予定を読み取り、期間・条件で整理して提示する。読み取り専用。予定の作成・変更は依頼があっても
`memory/delegation.md` に従い事前提示→承認を経る（本スキルの範囲外）。

## 実行手順

### Step 1: 期間・条件を確認する

- 「今日」「今週」「来週」「〇月〇日」など期間を特定する
- 特定の会議名・参加者で絞り込む場合は条件を把握する
- 複数のアカウントがありそうなら、どのカレンダーか確認する

### Step 2: 手段を解決する（`memory/service-capabilities.md` の解決順）

1. **コネクタ／MCP**：セッションにカレンダー系ツール（例：`list_events` / `search_events` /
   `list_calendars` を持つサーバー）があればそれを使う。期間と検索語を渡して取得する
2. **ブラウザ操作**：環境が対応していれば `https://calendar.google.com`（または該当サービス）を
   対象期間のビューで開いて読み取る
3. **手動アシスト**：上記が無ければ「カレンダーの {期間} の予定を貼り付けてください」と依頼し、
   貼り付けられた内容を整理する

### Step 3: 結果を整理して提示する

**予定一覧の場合**:
```markdown
## {期間} のスケジュール

### {日付（曜日）}
- {時刻} ── {予定名}（{場所/会議URL}）
- {時刻} ── {予定名}

**空き時間**: {空き時間帯をリスト}
```

**特定予定の検索結果**:
```markdown
## 「{検索キーワード}」の予定

- {日時}: {予定名}（{詳細}）
```

### Step 4: 関連する状況を提示する（オプション）

予定の内容から Backlog チケット・プロジェクト状況・約束台帳と紐付けて補足する
（例：「この会議はプロジェクトAに関連。status.md の現状: …／台帳の未完了: …」）。
準備が要る会議なら準備物を提案する（`/morning-brief` と同じ観点）。

## 注意事項

- 予定の変更・削除はしない（読み取り専用）
- 個人的な予定内容は要約のみ提示し、詳細をファイルに記録しない
- 取得に失敗した場合は手段を1段落として続け、何が使えなかったかをユーザーに報告する
