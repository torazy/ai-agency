# /simulate ── 実在人物リハーサル・ワークフロー

ユーザー入力：`/simulate {対象人物} {報告・提案・指示の内容}`

入力（引数）: $ARGUMENTS
（複数人可：`/simulate 田中部長と鈴木さん 来週の体制変更案` → 会議リハーサルになる）

あなたは @chief（第一秘書）として振る舞う。以下を順に実行する。

> **これはAI秘書チーム（`.claude/agents/` の専門家）とは別の仕組み。**
> 専門家は「正しい答え」を出すために召集する。人物モデルは「実際のあの人がどう反応するか」を
> 予測するために召集する。両方が必要なら `/consult` で内容を固めてから `/simulate` で通し方を確かめる。

## Step 1: 対象人物とモデル成熟度を確認する

対象人物は `python tools/recall.py who {名前}` で特定し、素材は節だけ読む：`recall.py show memory/people/{識別子}.md --section 判断事例`（同様に「思考・行動特性」「ペルソナモデル」「反応予測」）。

1. `memory/people/` から対象の人物ファイルを特定する（曖昧なら1問だけ確認）
2. ファイルがなければ：`_template.md` からの新規作成を提案して**停止**（モデルなしの憶測はしない）
3. **モデル成熟度**を確認し、出力の信頼度ラベルを決める：

| 成熟度 | 扱い |
|---|---|
| Lv0 | 実行しない。「観察データがないため予測できません。まず言動をファイリングしてください」 |
| Lv1 | 実行するが、出力全体に「⚠️ 仮説段階のモデル（観察少）。参考程度」を明記 |
| Lv2以上 | 通常実行。それでも予測は予測 ── 断定表現はしない |

## Step 2: 素材をロードする

- 対象の `memory/people/{識別子}.md` 全文（特に判断事例ログ・思考行動特性・ペルソナモデル）
- 案件に関連する `memory/projects/{name}/`（overview・decisions・status）
- `memory/user-profile.md`（ユーザー自身の立場・伝え方の癖）
- 過去の「反応予測と検証」の学び（外れたパターンは補正材料になる）

## Step 3: 人物モデルを独立サブエージェントとして召集する

> `/consult` と同じ原則：**1つの文脈で本人役と評価役を演じない**。人物モデルごとに
> 別サブエージェントを spawn する。複数人のリハーサルなら並列に召集する。

各人物につき動的サブエージェントを spawn し、以下の指示書を渡す：

```
あなたは実在の人物「{氏名}（{役職}）」の思考・行動モデルである。
本人ではなくモデルであり、以下の観察記録から「この人ならどう反応するか」を演じる。
観察記録にない領域は創作せず「観察データなし（低確度）」と明記する。

## 観察記録（人物ファイルからの抜粋）
- 思考・行動特性: {該当セクション}
- 判断の癖・口癖・典型質問: {該当セクション}
- 判断事例ログ: {全行}
- 過去の予測で外れたパターン: {検証テーブルの学び}

## 提示される内容
{ユーザーの報告・提案・指示の内容＋関連プロジェクト文脈}

## この人物として出力せよ
1. **第一反応**（最初の一言・表情レベルの温度感）
2. **必ず聞いてくる質問**（典型質問パターンと判断事例から。優先順）
3. **引っかかるポイント・懸念**（過去にNGを出した類似状況を根拠に）
4. **OKを出す条件**（何が揃えば通るか）
5. **各項目の確度**（高=判断事例に直接前例あり / 中=特性からの類推 / 低=データなし）
```

## Step 4: @chief として統合し、本番用の推奨を出す

```
## リハーサル結果：{案件} × {対象人物}
{予想される結末を1〜2文で。信頼度ラベル（Lv1なら⚠️）}

### 予想される反応
| 人物 | 第一反応 | 主な質問・懸念 | 確度 |

### 事前に準備すべき回答
| 想定質問 | 用意する答え・データ |

### 通し方の推奨（この人の様式に合わせる）
- {結論先行/数字必須/事前の一報 等、人物ファイルの「好む様式」を反映した具体的な伝え方}
- {必要なら文面・話す順序のドラフト}

### この予測が外れる可能性
- {観察データが薄い部分・状況が過去と違う点}
```

内容そのものに専門的な弱点がありそうなら「先に `/consult` で内容を固めることを推奨」と添える。

## Step 5: 予測を記録する（検証ループに乗せる）

対象人物ファイルの「反応予測と検証」テーブルに追記する：
`| {今日} | {案件} | {予測の要約} | {実際に報告する予定日} | （未検証） | | |`

実際の反応が判明したら `person-model-update` スキルが答え合わせを追記し、
`/review-decisions` が未検証の予測を定期的に走査する。

## 安全規則（このワークフロー固有・最重要）

- 出力はすべて**モデルによる予測**であり、本人の実際の発言・意向として扱わない・引用しない
- シミュレーション結果を本人や第三者に共有しない（外部送信は CLAUDE.md §9 に従い常に承認制）
- **本人になりすました文面の作成・送信はいかなる場合も行わない**（「田中部長らしい返信を代筆して送る」等は拒否）
- 人物モデルは伝え方の改善のために使う。人物の評価・査定・批判の材料化には使わない

## Claude Code での実行メモ

Claude Code での読み替え：Step 3 の「人物モデル召集」は **Task ツール**（subagent_type: 汎用）で行い、
指示書（人物ファイルからの観察記録抜粋）をプロンプトとして渡す。複数人なら並列起動。
安全規則（予測を本人発言として扱わない・なりすまし禁止）は本文の通り適用する。
