# モデルの使い分け（model-tiering）

軽量モデルの失敗そのものは無害だが、その結果が `memory/`（正典）に書き込まれると、以後すべての判断が
汚れた記憶の上で行われる。だから**分担の軸は「記憶への書き込みの有無」**。

| 層 | 担当タスク | 想定 |
|---|---|---|
| **閲覧・確認系** | 状況確認・台帳やブリーフの参照・リマインド・下書きのたたき台・`recall.py` での検索 | 軽量モデルで可 |
| **記憶書き込み系** | /intake・/update・commitment-track・person-model-update・decisions 記録・memory-review の手直し | 中位以上 |
| **判断・生成系** | /consult・/discuss・/simulate・/incident・成果物作成 | フロンティアモデル |

- グレーゾーン（既存行の状態更新など定型の軽微な書き込み）は軽量でも可
- 新規ファイルの作成・関連付け・人物観察の記録は必ず上位層で行う
- どの層でも安全規則（CLAUDE.md §9）と承認原則は同じ
- サブエージェントの `model` を下げるときは、その作業が閲覧系に収まるか（`memory/` に書かないか）を先に確かめる
