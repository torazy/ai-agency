# メモリ更新スキル

会話の中で生まれた知識・決定・パターンをメモリシステムに記録するプロセス。

## トリガー条件

以下のいずれかが発生したとき自動的に起動する：

- 重要な決定・合意が会話の中でなされた
- ユーザーのパターン・好みが観察できた
- タスクが完了した
- 新しいドメイン知識が共有された
- エラー・失敗から学びが得られた
- プロジェクトの状態が変わった

## 実行手順

### Step 1: 記録すべき情報を特定する

会話全体を振り返り、記録価値がある情報を選別する：

- **記録すべき**: 再利用できる知識、今後の判断に影響する決定、覚えておくべきパターン
- **記録不要**: 一時的な雑談、既に記録済みの情報、推測の域を出ない内容

### Step 2: 適切な記録先に書く

| 情報の種類 | 記録先 | 操作 |
|---|---|---|
| プロジェクトの決定事項 | `memory/projects/{name}/decisions.md` | 追記 |
| プロジェクトの現状変化 | `memory/projects/{name}/status.md` | 更新 |
| ユーザーの好み・パターン | `memory/user-profile.md` | 追記 |
| 業務上の学び・ドメイン知識 | `memory/insights.md` | 追記 |
| 今の優先事項の変化 | `memory/situation.md` | 更新 |
| 新しいサービス座標 | `memory/projects/{name}/overview.md` | 追記 |

### Step 3: 既存内容と整合性を確認する

書き込み前に対象ファイルを読み、矛盾がないか確認する。
矛盾がある場合はユーザーに確認してから更新する。

### Step 4: 更新内容を簡潔に報告する

```
📝 メモリを更新しました：
- {ファイル名}: {何を記録したか（1行）}
```

大きな変更でない限り詳細を長々と説明しない。

## タスク完了時の記録テンプレート

タスク完了後に `memory/task-log/YYYY-MM.md` に追記する：

```markdown
## YYYY-MM-DD: {タスクの概要}

**実施内容**: 
**関連Backlogチケット**: #{番号}
**関連GitHubリポジトリ**: {owner/repo}
**関連プロジェクト**: {プロジェクト名}
**新たに学んだこと**: 
**次回への申し送り**: 
```

## 注意事項

- ユーザーが「覚えておいて」と言った場合は必ず記録し、記録したことを報告する
- 推測・未確認情報は記録しない（事実のみ）
- 更新報告は簡潔に。作業の邪魔にならない程度に留める
- `delegation.md` の禁止事項に抵触する更新は行わない
