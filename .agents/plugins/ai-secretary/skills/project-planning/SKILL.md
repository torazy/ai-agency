# プロジェクト計画スキル

プロジェクトの計画立案・タスク分解・スケジュール作成を支援する。

## 実行手順

### Step 1: 既存の文脈を収集する

- `memory/projects/{name}/overview.md` ── 目標・制約・関係者
- `memory/projects/{name}/decisions.md` ── これまでの決定事項
- `memory/projects/{name}/issues.md` ── 既知のリスク・課題
- Backlog: 既存チケットの確認（重複を避けるため）

### Step 2: 要件・制約を整理する

```markdown
## プロジェクト計画：{プロジェクト名}

### 目標
- {何を達成するか}

### 制約
- **期限**: {日付}
- **人員**: {人数・役割}
- **予算**: {あれば}
- **技術制約**: {あれば}

### 前提条件
- {仮定していること}
```

### Step 3: タスクを分解する（WBS）

```markdown
### タスク分解

**フェーズ1: {フェーズ名}** （{期間}）
- [ ] {タスク1} ── {担当者} / {工数見積もり}
- [ ] {タスク2} ── {担当者} / {工数見積もり}

**フェーズ2: {フェーズ名}** （{期間}）
- [ ] {タスク3}
- [ ] {タスク4}

**マイルストーン**:
- {日付}: {成果物・チェックポイント}
- {日付}: {成果物・チェックポイント}
```

### Step 4: リスクを特定する

```markdown
### リスク

| リスク | 発生確率 | 影響度 | 対策 |
|---|---|---|---|
| {リスク1} | 高/中/低 | 高/中/低 | {対策} |
```

### Step 5: Backlogチケット起票を提案する

```
## 次のアクション

計画が確定しました。以下のチケットをBacklogに起票しますか？

- 「{タスク1}」── 担当: {担当者} / 期限: {日付}
- 「{タスク2}」── 担当: {担当者} / 期限: {日付}

▶ 起票してよいですか？（`backlog-manage` スキルで実行します）
```

承認後、`backlog-manage` スキルを使って順次起票する。

### Step 6: 計画をファイリングする

```
この計画を `memory/projects/{name}/context/project-plan.md` に保存しますか？
```

## 注意事項

- 工数見積もりは幅を持たせる（例：「3〜5日」）
- 依存関係が複雑な場合はガントチャート形式のテキストで表現する
- ユーザーが承認していない前提（担当者・期限等）は仮置きとして明示する
